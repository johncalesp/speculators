# Train a DFlash drafter for Qwen2.5-VL

These recipes train a **DFlash draft model** against `Qwen/Qwen2.5-VL-7B-Instruct` or a compatible, already fine-tuned Qwen2.5-VL checkpoint:

- `examples/train/dflash_qwen2_5_vl_7b_visionarena_online.sh` uses **VisionArena only**.
- `examples/train/dflash_qwen2_5_vl_7b_requests_online.sh` uses customer chat request bodies, such as product attribute extraction requests.

The customer recipe uses the public Qwen model as a placeholder. Set `MODEL` to the customer's SFT checkpoint when available. That same checkpoint must generate the responses and provide the hidden states. These scripts do not perform supervised fine-tuning of the target itself, and a drafter trained against the public placeholder has not been validated against a private SFT model.

## Requirements and installation

Run commands from this repository's root on Linux with Bash, Git, `curl`, NVIDIA drivers (`nvidia-smi`), and CUDA-capable GPUs. Default allocation is four GPUs: all four regenerate responses, then GPUs 0–1 serve hidden states while GPUs 2–3 train. Two sufficiently large GPUs also work with the overrides below. The smoke recipe is intended for H200-class GPUs; smaller cards may need more tensor parallelism and lower image/sequence limits.

Python 3.12 is the tested interpreter. Install the repository (the scripts are not included in a PyPI-only install):

```bash
git clone --branch jcalderon/vlm-experimentation https://github.com/johncalesp/speculators.git
cd speculators
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install 'vllm==0.25.1' -e . Pillow aiohttp
```

The basic Python packages are vLLM for serving/rendering, PyTorch for training, Transformers for model/tokenizer configuration, Datasets/PyArrow for dataset I/O, Hugging Face Hub, Pillow for image validation, and aiohttp/tqdm for regeneration. Installing `-e .` also installs this checkout's `hs-connectors`, used to transfer hidden states. No separate FlashAttention package is required for the DFlash recipe.

An alternative with a prebuilt CUDA/PyTorch stack is `vllm/vllm-openai:v0.25.1`. Install Git **inside the container** as well (`apt-get update && apt-get install -y git`) so `train_command.txt` can capture the source revision. Inside that image, create a virtual environment with `--system-site-packages` and install `-e . Pillow aiohttp`. Launch the container with GPU access, adequate shared memory (the smoke tests use `--shm-size=16g`), and mount the repository, output storage, and Hugging Face cache. Absolute image paths must be visible to both server and trainer.

Separate environments are also supported: set `PYTHON=/path/to/speculators-venv/bin/python` and `VLLM_PYTHON=/path/to/vllm-venv/bin/python`. The serving environment needs vLLM and Transformers; the training environment needs this repository and the packages above. Both processes must share the output directory.

Reserve space for model weights, the dataset cache, exported images, and checkpoints. Images remain necessary throughout training: the prepared dataset stores file references, not image bytes. Hidden-state files are generated on demand under `OUTPUT_DIR/hidden_states` and deleted after consumption. Server logs are under `OUTPUT_DIR`.

## VisionArena

Download once, or use an existing Hugging Face cache:

```bash
hf download lmarena-ai/VisionArena-Chat --repo-type dataset
bash examples/train/dflash_qwen2_5_vl_7b_visionarena_online.sh
```

Export reads the local cache by default (`HF_HOME`, normally `~/.cache/huggingface`); it does not download the dataset. `DATASET_PATH=/path/to/visionarena` can identify a local snapshot containing Parquet shards. `EXPORT_ALLOW_DOWNLOAD=1` explicitly enables Hub streaming instead. The model must also be cached or downloadable.

Defaults export 5,000 English conversations, retain up to two user turns, cap preprocessing at 5,000 conversations, and train five epochs. VisionArena's existing assistant answers are discarded and regenerated by `MODEL`. Keep every language with `EXPORT_LANGUAGE=`. Set `EXPORT_LIMIT` and `MAX_SAMPLES` explicitly for your chosen scale:

```bash
OUTPUT_DIR=./output/visionarena_50k \
EXPORT_LIMIT=50000 MAX_SAMPLES=50000 EPOCHS=2 \
bash examples/train/dflash_qwen2_5_vl_7b_visionarena_online.sh
```

This launcher no longer accepts Nemotron or mixed datasets. Use a fresh output directory when moving from an earlier mixed run.

## Customer request bodies

Use [the valid JSON example](https://github.com/johncalesp/speculators/blob/jcalderon/vlm-experimentation/examples/data/vlm_attribute_request.json). It contains the system instruction, product description, base64 image, temperature, token limit, and token biases from the supplied curl use case. Its image is a synthetic red square for testing, not a product photo. The original `curl_example.txt` is shell documentation, includes an unquoted model substitution and literal line breaks in JSON strings, and its embedded PNG has an invalid checksum. Do not feed that shell text to the converter.

For thousands of records, write **one complete request object per line** in a UTF-8 `.jsonl` file. Use a JSON encoder (`json.dumps`) so newlines inside text are escaped. A `.json` file can instead contain one object or a list of objects. An optional `id` distinguishes otherwise identical records.

```python
import json

with open('requests.jsonl', 'w', encoding='utf-8') as output:
    for request in customer_requests:  # iterable of request-body dictionaries
        output.write(json.dumps(request, ensure_ascii=False) + '\n')
```

The converter:

- Preserves the optional system message, user text, image order, and multiple images. Existing assistant history is dropped and regenerated sequentially by the target.
- Accepts PNG/JPEG/WEBP as `data:image/...;base64,...`, `file:///absolute/path`, or a plain local path in `image_url.url`. Relative paths resolve against the input file's directory. Local images are copied into the output's image directory; HTTP image URLs must be downloaded first. Only image `detail=auto` is supported; control resolution through `MM_PROCESSOR_KWARGS`.
- Validates images and stores one copy per content hash. Records are streamed for JSONL, and identical requests with the same ID are deduplicated. Memory use includes the set of exported IDs, not every base64 image.
- Carries `temperature`, `top_p`, `top_k`, `min_p`, `max_tokens`, `stop`, `seed`, presence/frequency/repetition penalties, and `logit_bias` into regeneration. `REGEN_MAX_TOKENS` caps each record's `max_tokens`; explicit `REGEN_SAMPLING_PARAMS` overrides other per-record sampling settings.
- Ignores the input `model` and `stream`; the launcher selects `MODEL` and uses non-streaming generation. Rejects unsupported fields such as tools and structured-output constraints instead of silently discarding them. Do not include authentication headers or bearer tokens in dataset files.
- Reports the source file and record number on invalid input, and leaves a previous export intact on failure.

Inspect the CPU conversion independently:

```bash
python scripts/export_vlm_requests.py \
  --input requests.jsonl \
  --image-dir ./output/customer_preview/images \
  --outfile ./output/customer_preview/prompts.jsonl
```

The standalone converter accepts multiple files after `--input`. The full launcher accepts one file via `REQUESTS_FILE`; concatenate request JSONL shards first if necessary. Choose a separate `OUTPUT_DIR` for training, as the launcher records its own configuration before export.

```bash
REQUESTS_FILE=/data/requests.jsonl \
MODEL=Qwen/Qwen2.5-VL-7B-Instruct \
OUTPUT_DIR=./output/customer_dflash \
EXPORT_LIMIT=10000 MAX_SAMPLES=10000 EPOCHS=2 \
bash examples/train/dflash_qwen2_5_vl_7b_requests_online.sh
```

For the actual experiment, replace `MODEL` with the private SFT repository ID or a local checkpoint directory. Authenticate to Hugging Face before running if needed. It must expose the same Qwen2.5-VL architecture, tokenizer, and chat template; another architecture may require different layer IDs and training settings. Never change targets in an existing output directory. Pin a downloaded model snapshot or immutable local checkpoint for reproducibility.

## Small end-to-end smoke test

This runs all five stages: export, target response regeneration, hidden-state serving, rendering/preprocessing, and DFlash training/checkpointing. A one-layer drafter and twelve records verify execution, not model quality or speculative-decoding speed.

```bash
export EXPORT_LIMIT=12 MAX_SAMPLES=12 EPOCHS=1
export SEQ_LENGTH=2048 REGEN_MAX_TOKENS=128 REGEN_CONCURRENCY=4
export MAX_ANCHORS=32 BLOCK_SIZE=4 NUM_LAYERS=1 NUM_WORKERS=0
export MM_PROCESSOR_KWARGS='{"max_pixels":200704}'
export REGEN_GPUS=0 REGEN_DP=1 REGEN_TP=1
export EXTRACT_GPUS=0 EXTRACT_DP_SIZE=1 EXTRACT_TP=1
export TRAIN_GPUS=1 NUM_TRAIN_GPUS=1 SERVER_EAGER=1

MAX_TURNS=1 OUTPUT_DIR=./output/visionarena_smoke \
bash examples/train/dflash_qwen2_5_vl_7b_visionarena_online.sh
```

For a synthetic customer-data smoke test, create twelve records from the valid example. Different IDs keep each record in the export. Repeated synthetic images are useful for execution testing only; use distinct real products for meaningful training and validation.

```bash
python - <<'PY'
import json
from pathlib import Path
request = json.loads(Path('examples/data/vlm_attribute_request.json').read_text())
with open('requests_smoke.jsonl', 'w') as output:
    for index in range(12):
        output.write(json.dumps(request | {'id': f'smoke-{index}'}) + '\n')
PY
REQUESTS_FILE=./requests_smoke.jsonl OUTPUT_DIR=./output/requests_smoke \
bash examples/train/dflash_qwen2_5_vl_7b_requests_online.sh
```

Successful runs leave `prepared/state.json`, checkpoint weights/configuration under `checkpoints/0`, and `checkpoints/train_command.txt`. Inspect `conversations.errors.jsonl` and server logs if regeneration fails. The launcher refuses to proceed when requests are missing from regenerated output. A `truncated` flag in conversation metadata means the response reached its token limit; increase `REGEN_MAX_TOKENS` for a real run if needed. Very long records may also be excluded by preprocessing's sequence limit.

See the [recorded H200 validation](../../validation/vlm_dflash_smoke_2026_09_17.md) for the tested source revision, exact environment, and provenance artifacts.

## Configuration and resuming

| Variable                                 | Default                                    | Purpose                                                                       |
| ---------------------------------------- | ------------------------------------------ | ----------------------------------------------------------------------------- |
| `MODEL`                                  | `Qwen/Qwen2.5-VL-7B-Instruct`              | Target for generation and hidden states                                       |
| `OUTPUT_DIR`                             | Dataset-specific directory under `output/` | Images, data, configuration, logs, checkpoints                                |
| `EXPORT_LIMIT` / `MAX_SAMPLES`           | `5000` / `5000`                            | Export limit / preprocessing conversation cap; empty `MAX_SAMPLES=` keeps all |
| `SEQ_LENGTH`                             | `8192`                                     | Serving and training sequence limit                                           |
| `EPOCHS` / `LR`                          | `5` / `3e-4`                               | Training epochs and learning rate                                             |
| `REGEN_MAX_TOKENS` / `REGEN_CONCURRENCY` | `2048` / `32`                              | Response budget and concurrent conversations                                  |
| `REGEN_SAMPLING_PARAMS`                  | `{}`                                       | JSON sampling overrides                                                       |
| `MM_PROCESSOR_KWARGS`                    | `{"max_pixels":1003520}`                   | Shared image processing settings for both servers                             |
| `LIMIT_MM_PER_PROMPT`                    | `{"image":4}`                              | Maximum images in the whole conversation                                      |
| `TARGET_LAYER_IDS`                       | `2 14 25`                                  | Qwen2.5-VL-7B hidden layers; extraction also includes final layer 28          |
| `BLOCK_SIZE` / `NUM_LAYERS`              | `16` / `5`                                 | Draft block size and layer count                                              |
| `MAX_ANCHORS` / `DRAFT_VOCAB_SIZE`       | `3072` / `32000`                           | Training anchors and reduced draft vocabulary                                 |
| `CHECKPOINT_FREQ` / `SAVE_BEST`          | `1` / empty                                | Epoch checkpoint interval / set nonempty to keep best                         |
| `NUM_WORKERS`                            | `12`                                       | Training data-loader workers; `0` is useful for debugging                     |
| `SERVER_PORT` / `SERVER_START_TIMEOUT`   | `8000` / `1800`                            | Local server port / startup timeout in seconds                                |
| `SERVER_EAGER`                           | empty                                      | Nonempty disables server CUDA graphs for smoke tests                          |

GPU lists contain physical indices reported by `nvidia-smi`; the launcher sets `CUDA_VISIBLE_DEVICES` separately for each process. Extraction and training lists must be disjoint. Each serving list's length must equal its DP × TP product; `NUM_TRAIN_GPUS` must equal the training list's length. Qwen2.5-VL-7B has 28 attention heads, so use TP 1, 2, or 4 with the default four-GPU allocation.

Rerun the same command to resume. Exported images are reused; completed responses are skipped; an unchanged prepared dataset is reused; training resumes from saved checkpoints. Raise `EPOCHS` if the previous run already completed its requested epochs. `SKIP_REGEN=1` skips regeneration only when all exported requests already have responses. `CHECKPOINT_DIR` can override the checkpoint location.

`pipeline_config.json` pins data selection, request-file hash, model, generation settings, and image/sequence settings. If any change, choose a fresh `OUTPUT_DIR`. Old output directories without this manifest are rejected. Prepared data is additionally checked against the regenerated conversation content hash. Do not mutate image files or model checkpoints in place during a run.

The default validation split is row-based. For real customer data, prevent repeated or related product images from crossing train/validation sets before preparing a quality evaluation; the synthetic smoke test does not measure generalization.

Keep `pipeline_config.json`, input records or dataset revision, prompts, regenerated conversations, and `train_command.txt` with each run. The training artifact records the Git SHA, package versions, distributed world size, and training argv. Include it when sharing checkpoints. If evaluating and publishing results, also include `eval_command.txt` from the evaluation output directory.
